# 文字入れ・画像生成の仕様

概要は [README](../README.md) にも記載。ここでは実装上の不変条件を集約する。

## 文字配置
- **位置が上/下（横書き）**: 左揃え、画像幅に収まらない場合は改行。
- **位置が左/右（縦書き）**: 上揃え、画像高さに収まらない場合は次の列へ（右から左）。
- 縦書き時は句読点・括弧の回転処理あり。

## フォントサイズ
- 画像の短辺基準で自動計算（横書き・縦書き共通）。基準 `Math.min(width, height) / 14`（約14文字）、下限14px・上限500px。
- サイズ係数: 小(0.75) / 中(1.0) / 大(1.4) / 特大(2.35)

## 絵文字のフォント
絵文字は本文フォント（ふい字等）に関わらず必ず同梱の **Noto Emoji（モノクロ）** で描く。判定は書記素単位（[grapheme.ts](../src/lib/text/grapheme.ts) の `isEmojiGrapheme`）。

- **pitfall**: ふい字は ☀☁❤♨✈ など73字、怖い明朝は ™▪✂ など8字を **cmap に持ちながら中身が空グリフ**。フォントスタック末尾のフォールバックは「cmap に無い」ときしか効かないため、本文フォントを先頭に置いたままだと空グリフが採用され**絵文字が無言で消える**（☀️ が出ない不具合の原因）。カレンダーの © を Noto 固定にしているのも同じ理由。
- 対策として、書記素が絵文字のあいだだけフォントスタックを絵文字優先（[`emojiFontStack`](../src/lib/image/text.ts)）に差し替える。1書記素ごとの `measureText` / `fillText` は必ず [`withGraphemeFont`](../src/lib/image/text.ts)（計測は `measureGrapheme` / `measureLineWidth`）を通すのが不変条件（計測と描画で別フォントになると字送りがずれる）。
- Noto Emoji が持たない文字（★ ♪ ☆ など）は後段の本文フォントへ落ちるので巻き込まれない。
- 絵文字だけの投稿で本文フォント名を表示しないのも同じ前提（`hasNonEmojiText`）。

## 文字の影
- 視認性のため全文字に影を追加。薄い色（白・緑・黄・桃・橙）→黒影、濃い色（赤・青・茶）→白影。
- アレンジ「ネオン」「ハンコ」は専用の描画に分岐するのでこの影は付かない。

## アレンジ「ハンコ」（[src/lib/image/stamp/](../src/lib/image/stamp/)）
朱文（＝枠線と文字だけを印肉色で描き、地は塗らない）の印章。分割は
`layout.ts`（印面の寸法・純粋計算）/ `ink.ts`（かすれマスク・純粋計算）/ `color.ts`（印肉色）/
`rng.ts`（決定的乱数）/ `render.ts`（skia 描画）。純粋計算の3つは単体テスト対象。

- **不均一さはピクセル側にしか無い**。印章は彫ってあるので文字は動かない＝字ごとの位置・角度のランダム化はしない
  （手書きに見えてしまう）。印影をオフスクリーンに完全な形で描き、ノイズを `destination-out` で削って
  かすれを作る。枠は直線のまま縁だけが自然に欠ける。
  - **pitfall**: 旧実装は「文字ごとにアルファを変える」かすれだった。かすれは文字の区切りと無関係な面のムラなので、
    字ごとに濃さが違うと「かすれ」ではなく「薄い字」に見える。
  - **pitfall**: 地（背景）を枠とは別パスの矩形塗りで描いていたため、手描き風に歪めた枠から必ずはみ出していた。
    朱文では地を塗らない＝構造的に起こらない。
  - 抜けの境界のなだらかさは層ごとの `softness`。大きいと1箇所あたりが広く滲んで印影全体がぼやけるので、
    **1箇所は小さく引き締め、箇所数（`frequency`・`pinholes`）で量を稼ぐ**。
  - **かすれの強さは枠と文字で違う**。枠は欠けてよい（縁が欠けるのが印影らしさ）が、文字は抜けると画数が減って
    別の字に見えたり読めなくなるため、削り量に上限（`RENDER.charMaxCut`）を掛けて「色が薄くなる」までに留める。
    枠側にも上限（`frameMaxCut`）を置いて完全な抜けだけ僅かに抑える＝文字との質感の差を開かせない。
    実装は枠と文字を別レイヤーに描き、**同じマスクを別の `globalAlpha` で** `destination-out` する
    （マスクは層を1枚に合成してから使う。層ごとに強さを絞ると重なりで上限が保証できない）。
- **行揃え・改行の扱いは通常描画と同じ**（横書き＝左揃え・縦書き＝上揃えで右の列から。改行は行/列の区切りで、
  縦書きの列分割は [`splitTextIntoColumns`](../src/lib/image/text.ts) を共用）。文字ブロック全体は枠の中央に置くが、
  行ごとに中央寄せすると折り返した2行目以降が「位置＝上/下は左揃え」の規則から外れる。
- **絵文字の送り幅は等幅セルに収まらない**。実測で `fontSize` の約1.27倍あるため、等幅セル（＝`fontSize`）前提で
  印面の幅を決めると**絵文字が枠を突き抜ける**。`stampAdvance` で絵文字だけ実測に切り替え、折り返し
  （`splitTextIntoLines` の `advanceOf`）・印面幅・字送り・縦書きの列幅すべてで同じ幅を使う。
  枠の無い通常描画は画像内に収まれば済むのでセル中央寄せ（`emojiCellOffsetX`）で足りるが、ハンコは枠があるため足りない。
- **にじみ・ハローの大きさに絶対値の下限を置かない**。フォントサイズ下限（14px）の小さい印では、
  下限1.5pxのような値が fontSize 比で数倍に効いて、小さい印だけ不釣り合いに太くぼやける。上限のみ設ける。
- **枠は文字の実グリフに寄せる**。`fontSize` は em の高さで和文グリフはその 0.86 前後しか占めないため、
  行送りをそのまま枠にすると文字の周りが間延びして印章に見えない。両端は送りではなくグリフ高さで詰める。
  `textBaseline="middle"` は欧文基準で和文が下寄りに出るので、代表字（国）の実測から中心のズレを補正する。
- **縦横比**は上下限（0.28〜4.0）で緩和するが、短辺を広げるのは 1.6 倍まで。比だけで正方形に寄せると
  「枠だけ大きく中身は余白」になる（細長い一行印・落款印は実在する）。空いた分は字送り・行送りを伸ばして埋める。
- **傾き**（[tilt.ts](../src/lib/image/stamp/tilt.ts)）は 1.5〜5.5°（大きいほど珍しい三角分布）で、向きは常に右肩上がり。
  手で押した印はまず真っ直ぐにならないので下限を設ける（0 中心の分布のままだと「ほぼ水平」ばかり出て傾けている意味が無い）。
  左右ランダムにすると右肩下がりが混じって「傾け損ない」に見えるため向きは固定。回転後も margin 内に収まる角度に制限する。
  - **印面が大きいほど角度を小さくする**（画像の辺に占める割合 0.3 以下＝等倍 → 0.9 以上＝0.4倍）。
    目に入るのは角度ではなく端の持ち上がり量（長辺 / 2 × sin角度）なので、同じ角度でも大きい印は
    「歪んで押した」ように見え、小さい印は数pxしか動かず効果が出ない。基準を横幅ではなく**長辺**にするのは、
    縦書きの細長い印が「幅が細いから大きく傾けてよい」と判定されると下端が横に大きくずれて同じ問題が起きるため。
- **色**は文字色オプションの色相を保ったまま彩度・明度を印肉相当（S≥0.8・L=0.33〜0.45）に正規化する。
  明るい黄や淡い桃のような印肉は存在しないため。無彩色（白）は色相が無く正規化しても灰色にしかならないので、
  そのまま使う（朱に置き換えると「白を選んだのに赤いハンコが出る」ことになる）。
- **可読性はハローで確保する**。ハンコには縁取りも影も無く朱文は地も透明なので、写真と同系色だと沈む。
  印影と同じ形（かすれの抜け込み）の反対色シルエットを最下層に敷く。色は選択された色名ではなく
  **印肉化した後の相対輝度**で決める（正規化で緑・橙などは元の色と明るさが変わるため）。
  - **pitfall**: ぼかしただけでは効かない。印影は細い線の集まりなので、ぼかしたシルエットは大半が
    インクの下に隠れて外へ出ない。8方向へ実際に広げてから軽くぼかす（`haloLayer`）。
- **乱数は入力から導いた seed の擬似乱数**（`hashString` + `mulberry32`）。`Math.random()` を直に使うと
  同じ入力でも押すたび印影が変わり、ゴールデンテストに載せられない（旧実装はこれで stamp だけ対象外だった）。

## 画像の取り扱い
- 生成画像はBlobURLで一時表示し離脱時に破棄。生成後のオプション変更で「再生成」ボタン有効化。「最初からやり直す」で全リセット。

## EXIF/メタデータ
- Orientationに従い自動回転（スマホ画像対応）。GPS・カメラ情報等は出力時に削除（プライバシー保護）。
- **撮影情報のオプトイン保存**（`cameraOption`: `none`/`show`/`detail`）。`show`=カメラのメーカー名・機種名のみ、`detail`=加えてF値・シャッター速度・ISO・焦点距離(+35mm換算)・レンズ名・露出補正・フラッシュを `Image.exifDetails`（JSON）へ保存。撮影日時・撮影方向（GPS方位）は取得しない。抽出は [parser.ts](../src/lib/exif/parser.ts)（`extractExif(input, {detail})`）、整形/サニタイズは [details.ts](../src/lib/exif/details.ts)。詳細ページでは機種名クリックでモーダル表示（`ExifDetailModal`）。

## 代替テキスト（ALT）
画像の代替テキスト。`text` と同じ経路に `altText` を1本通す配管（`PublishImageInput.altText` → `PostImageInput` → [post.ts](../src/lib/fediverse/post.ts)）。DBは `Image.altText`（VarChar1500・null=未設定）。
- **投稿先**: Mastodon=メディアの `description`／Misskey=ドライブの `comment`（**512字上限で切り詰め**）。未設定なら送らない。
- **Web**: [ImageUpload.tsx](../src/components/ImageUpload.tsx) の画像左上「ALT」バッジ（Mastodon風）→ [AltTextDialog.tsx](../src/components/AltTextDialog.tsx) で入力。生成には不要なので `/api/v1/generate` には送らず `/api/v1/post` の FormData にのみ相乗り。画像を変えたら破棄。上限1500字。
- **Bot（mention）**: 元投稿の添付メディアの `description` をそのまま引き継ぐ（[processor.ts](../src/lib/mention/processor.ts)）。**メール投稿は非対応**。
- **サービス側 `<img>`**: 主画像の alt は `altText || overlayText`（ALT未設定なら合成テキストにフォールバック）。装飾サムネ（`alt=""`）は対象外。
